# 50:50 消息监督与载体覆盖实验

在固定载体覆盖和累计曝光量的条件下，比较直接解码与真实换脸 BCE 等权和 75:25 加权。主要指标是未见载体经 Oldpan 换脸后的 15 位整串恢复。

## 固定训练条件

- N16、N64、N416 与 75:25 各组使用相同的载体 ID、消息顺序、载体与消息配对及评估配对。前 6000 步逐步复用原共享计划，后续逐步复用原曝光配额表。
- 三组均从与 75:25 相同的 `author64-swap-recovery-v2` 第 500 步编码器和解码器权重开始，使用新的 Adam。第 6000 步以后，各组从自己的 50:50 检查点恢复编码器、解码器、Adam 和数据游标。
- 每个样本的同一张水印图同时走直接解码和真实跨身份换脸，两路共用一个解码器。目标为 `MSE + 0.1 × 结构损失 + 0.5 × 直接 BCE + 0.5 × 换脸 BCE`。沿用冻结 Oldpan、冻结 BN 运行统计、`8/255` 扰动上限、学习率 `5e-6`、权重衰减 `1e-5`、FP32 和每步 16 个样本。N416 续训时沿用按身份加权的原曝光方案，每次更新两个身份各占一半损失权重。

## 更新和曝光节点

| 组别 | 等步数阶段 | 等曝光续训阶段 |
| --- | --- | --- |
| N16 | 6000 步 | 第 6000 步已达每图 6000 次 |
| N64 | 6000 步 | 第 12,000、18,000、24,000 步，每图 3000、4500、6000 次 |
| N416 | 6000 步 | 第 13,000、26,000、39,000 步，每图 500、1000、1500 次 |
| N416 通过续训判据后 | 从第 39,000 步恢复 | 第 78,000、117,000、156,000 步，每图 3000、4500、6000 次 |

N416 在第 39,000 步应用同一判据。第 26,000 和 39,000 步相对本组第 6000 步的新图整串恢复率，按来源组配对估计的两个 95% 区间下界均须大于零。第 39,000 步的恢复数还须至少与第 26,000 步持平。服务器核验后按判据决定是否继续。

## 结果比较

- 在每个共同节点上，按相同载体规模和累计训练步数逐条配对比较 50:50 与 75:25。续训后，同组别同节点也具有相同的单图曝光量。
- 比较固定的 556 个未见载体与消息配对上的换脸后整串率和 BER，用来源组配对 bootstrap 计算区间。分方向报告结果。512 个同图新消息配对用于区分已见载体适配和新图泛化。
- 直接解码和 PNG 读回用于检查直接可读性，JPEG 50 只作为辅助验证。记录 PSNR 与扰动预算。测试集保持封存。

结论对应单种子、两个身份、一个冻结换脸器和当前单分支水印编码器。

## 50:50 加 OFEA 的配对续训

从 N416 的第 117,000 步检查点分叉，两组使用该检查点的编码器、解码器、Adam 和后续采样序列。对照组权重为零，联合组在现有等权消息损失上增加 OFEA。训练循环调用一次 `forward_pair()`。换脸图参与消息 BCE，原身份重建与跨身份换脸分支的原生 64×64 Sigmoid 前特征参与 OFEA。特征平方误差按元素平均，再沿用现有的身份等权汇总。

在服务器项目根目录，将 `train_exposure.py`、`exposure_identity.py`、`audit_exposure.py`、`run_joint.py` 和 `launch_ofea.sh` 放入一个独立代码目录。以下命令会从下一个冻结批次估计梯度尺度，并运行两组各 1000 步。示例设备可按可用 GPU 修改。

```bash
code_dir=runs/author64-exposure-equal-ofea-20261111
bash "$code_dir/launch_ofea.sh" "$code_dir" 1000 cuda:3 cuda:0
```

启动脚本按两种身份中较大的梯度比例选择初始权重，使探测批次的加权 OFEA 梯度范数至多约为消息梯度范数的 10%。结果记录在 `steps-1000/probe.json`。训练在绝对步数 117,000、117,250、117,500、118,000 评价。每个节点的 `validation-*.jsonl` 保存消息恢复和质量，`identity-*.jsonl` 保存同一换脸输出的身份分数和完整消息判定。两组的 `audit-118000.json` 包含有效分母上的阻断率、整串恢复率及联合成功率。身份评价使用已绑定的阈值和验证参考图。
